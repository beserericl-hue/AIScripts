# Naming your supporting-evidence files so they route to the right Standard

You can upload many supporting files at once from **either** place:

- the editor toolbar's **Import file** button: select or drag several files together, or
- the **Review** page's **"Drop supporting files here"** panel.

Either way the system reads each file, decides which **Standard** and
**sub-specification** it belongs to, and then shows a **list of every file and
where it was filed**. Check that list before moving on. You always get the final
say: you can change any placement in the Review panel or the File Library.

> **Import file does not mean "file it under the page I have open."** With several files selected, each one goes where its own name and content say it belongs. Only a single file opens the preview so you can paste its text into the open section.

You can make the placement almost always correct, and usually exact, by how
you **name the file**. Two minutes of renaming saves a lot of re-assigning.

## The one rule that guarantees a correct match

**Start the filename with the Standard (and sub-spec, if you know it):**

| Name it like this | It routes to |
|---|---|
| `Standard 4 - HS Exit Survey 2022-2025.xlsx` | Standard 4 |
| `Std 11.a - Course Contents Curriculum Map.xlsx` | Standard 11.a |
| `4.b - Departmental Bylaws.pdf` | Standard 4.b |

Any of these forms works at the **start** of the name: `Standard 4`, `Std 4`,
`Std 4.a`, or just `4.a`. When the file names its Standard, the system files it
directly under exactly that Standard/sub-spec, with no guessing.

If a file supports **more than one** Standard, name it for the primary one and
add the others in the Review panel using the **"+ reference"** chips on the card.

## Appendix names work too, if your self-study says which Standard the appendix is

Many programs number their appendices instead, for example
`APPENDIX IV 9 Alumni Survey Data.pdf`. That works as long as your **self-study
text** connects the two:

1. Somewhere the narrative says which Standard the appendix belongs to, for example "Appendix IV, Standard IV Program Evaluation". The system reads this to learn that **Appendix IV = Standard 4**.
2. Where a sub-spec cites an item, write the appendix, the item number and the title **the same way the file is named**. For example, 4.c says "see Appendix IV Program Evaluation, 9 Alumni Survey Data", so `APPENDIX IV 9 Alumni Survey Data.pdf` is filed under **4.c**.
3. An item the narrative never cites is filed at the Standard level (Standard 4), ready for you to move to a sub-spec if you want.

Keep each item number for **one** document. Using the same number for two
different documents (for example 14 Competency Log and 14 Student Evaluation of
Agency), or two titles for one document (Memorandum of Agreement vs Memorandum
of Understanding), makes the match ambiguous.

**Web links:** a browser shortcut (`.url`) in the batch is saved as a **link** to
that page and filed the same way.

**Uploading the same file again** (same name and size) is reported as
**Already uploaded**. It does not create a second copy.

## If you'd rather not prefix the Standard or appendix

The system will still try to match by the file's **topic**. To help it:

- **Name the file by what it is about, not how it's handled.** Good: `HS Alumni Education Outcomes.pdf`, `Curriculum Map - Course Contents.xlsx`. Avoid words that describe the file rather than the subject, such as `FINAL`, `UPDATED`, `copy 2`, `Master List`, `TO SEND TO FACULTY`, `Draft`, `v3`. (One real example matched a curriculum map to the Faculty standard purely because the name ended "TO SEND TO FACULTY".)
- **Spreadsheets need extra help.** A workbook of numbers has little text to read, so the name carries almost all the meaning. Give it a descriptive name and/or put a clear title in the first cell, for example `Program Exit Survey Results 2022-2025`.

## What you'll see after every upload

| The list says | What it means |
|---|---|
| **Filed under Standard 4.c** | The name said exactly where it goes. It is already in your File Library there. |
| **Suggested 9.a, confirm in Review** | A topic match. Confirm or change it on the Review card. |
| **Unassigned, choose a Standard** | The system wasn't sure. The file is saved; pick its Standard in the File Library (Unassigned filter). |
| **Already uploaded** | The same file was uploaded before. Nothing new was created. |
| **Not uploaded, reason** | The file type isn't supported. The rest of the batch still uploaded. |
